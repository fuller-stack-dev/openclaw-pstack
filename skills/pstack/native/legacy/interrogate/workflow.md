## interrogate
For long routed phases, spawn announcing children (without `collect`; a collector is collected in the turn that spawned it) and use a short bounded native wait, then hand off pending run IDs and finish on resume under [the shared lifecycle](../../contract.md#collection-and-resume); never respawn accepted children or claim pending work complete.

1. Keep this route read-only. Freeze the caller’s files/diff or the full feature-branch diff against the appropriate base, exact head, surrounding callers/types and test context. State one clear intent paragraph grounded in the request, commits, existing PR and code; ask only when intent is genuinely unresolved. Challenge execution against that intent, not the goal itself.
2. Read the pinned source-only [reviewer template](./reviewer-prompt.md), [rubric](./rubric.md), [code-quality lens](./code-quality-review.md) and [lead-judgment framework](./lead-judgment.md). Translate their substantive review instructions into the native brief below; do not invoke upstream runtime APIs or register agents.
3. Resolve `interrogate reviewers` through pstack_route; launch BOTH independent native sessions_spawn reviewers concurrently with emitted arguments, identical intent/context/rubric and labels A/B. Read-only is a brief and inherited tool-policy constraint, not an invented sandbox flag. Collect full results. Required unavailable review is BLOCKED, never replaced by parent personas or a sequential pass. Attribute actual resolved models and disclose unavailable/unverified diversity; do not infer family from names.
4. Each reviewer covers relevant correctness/error/edge paths, idempotency/concurrency, root cause versus symptom, structural integrity, real behavioral verification, complexity and security. Read beyond the diff and trace actual callers/input paths for bugs and dangerous sinks. Apply ambitious structural simplification, canonical ownership/helpers, clean types/boundaries, direct interfaces, atomic updates and justified parallelism; flag ad-hoc branches, wrappers, casts and a file crossing 1,000 lines without strong structural justification. Do not force irrelevant lenses or invent findings to fill a review.
5. Require structured findings with severity critical/warning/nit, exact file:line or symbol, concrete mechanism, evidence/reasoning and an optional concrete suggestion. Distinguish broken behavior from preference; `no findings` is valid. No code edits, mutating tests, posted reviews or PRs.
6. Merge duplicates with every originating model retained, count findings per reviewer, and note explicit contradictions. Validate each finding against source/behavior. Consensus is high signal, but scrutinize lone correctness/security findings too. Dismiss impossible input paths, missing-context errors, pure preferences, inflated nits and premature abstractions with a reason; do not dismiss uncomfortable real defects. Apply `judgment and prose` routing for the lead verdict, using a real child when that selection requires it.
7. Return Intent, Reviewers (label, actual model, finding count), Act on, Consider, Noted, Dismissed, and Agreement Map. Put EVERY finding in one of the four buckets with model attribution and rationale; Act on names the harm, Consider the cost tradeoff, Dismissed the concrete refutation. The model-attributed Agreement Map gives agreement/disagreement counts, identifies shared findings and contradictions, and explains what that pattern means. Keep blocked reviewer coverage visible; no automatic repair.
8. Each reviewer returns the `interrogate-reviewer` [output contract](../../agent-briefs.md#panel-output-contracts): every lens dispositioned, structured findings with an inference flag, and a status consistent with those findings. Contract validity is shape evidence only; the lead still validates every finding against source.
